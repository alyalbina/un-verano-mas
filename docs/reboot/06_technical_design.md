# Архитектура проекта Godot

В v0.5 project.godot запускает scenes/reboot.tscn. Старые chapter1.tscn, courtyard.tscn и их сценарии сохранены. Новый слой не подменяет старые поля новыми значениями и не требует миграции завершённого театрального сюжета в несовместимую историю.

reboot_root.gd координирует состояние, UI, звук, сцену и короткие постановочные события. reboot_state.gd хранит каноническое состояние головоломки, сюжетные факты, локацию, посещения и подсказки. reboot_world.gd строит навигацию и визуализирует условия. cutscene_controller.gd отправляет именованные события по времени. reboot_ui.gd сохраняет компактный UI прежней версии. character.gd и audio.gd переиспользуются.

Поток действия: InputEvent → подход по AStarGrid → действие мира или drag → изменение State → проверка условий → отображение и запись. Кот управляется местной машиной состояний интереса в World. Его завершённое действие переводится в laundry_clear в State; движения и временный солнечный блик в сохранение не попадают. Частичная попытка доступна заново.

Puzzle framework сейчас специализирован под вступление. move_projection меняет две непрерывные величины с малым техническим округлением; move_board меняет направление. bridge_ready вычисляет связь; try_open принимает её только при всех предпосылках. stage возвращает этап для помощи. Для C02–C05 добавлять отдельные state-модули с тем же контрактом observe, serialize, restore, can_interact и completion, а не расширять один корневой switch бесконечно.

World state не дублируется визуальными флагами: фон без полотенца, закреплённая дверь и положение кота выводятся из State. Для большой главы вынести таблицы геометрии и зон в Resource/JSON, создать реестр puzzle id и декларативные события мира. Пока небольшой проверяемый модуль дешевле общего редактора головоломок.

# Сохранения и управление сценами

Новый файл user://photograph_v0_5.json имеет schema 5. На Windows используется настроенная папка UnVeranoMas в пользовательском каталоге Godot. Старый chapter1_v0_3.json не читается и не перезаписывается: сюжетные предпосылки несовместимы. Все постоянные решения записываются в новый файл после действий и переходов.

Запись сначала создаёт .tmp и затем переименовывает её. При запуске проверяются основной и временный файл. Повреждённый файл копируется с суффиксом .invalid до любой новой записи. Если сохранение повреждено и копия не удалась, автоматическая запись блокируется и игрок видит сообщение. restore сначала проверяет схему, типы, диапазоны, допустимые места и зависимости, затем применяет всё состояние одновременно.

Инварианты: проявление требует снимка; установка требует проявления; освобождение света требует зеркала; совмещение соответствует двум координатам при свободном свете; открытие требует непрерывной тени; посещение лоджии требует открытия; окончание вступления требует посещения. Положение открытой двери фиксируется. Внешние случайные флаги и несуществующие локации отклоняются.

Катсцена обнаружения имеет короткие события: поднять снимок, рассмотреть, проявить тень, реакция кота, подтверждение открытия правила. До финального подтверждения сохраняется photo=true и revealed=false. Перезапуск повторяет сцену, вместо восстановления позы посередине движения. Закреплённая дверь сохраняется до её декоративной анимации, поэтому перезапуск не создаёт тупика.

Панели останавливают PAUSABLE-мир, UI остаётся ALWAYS. Пауза во время постановки останавливает часы катсцены; закрытие возобновляет её. Переходы используют короткую затемняющую накладку для смены сцены, не для мистической окраски мира. При выходе остановлены все звуковые потоки. Временные файлы QA имеют отдельные имена и удаляются после теста.
